- 2026-08-23: Zarinpal callback_url made config-driven for the `.ir` cutover. Added `normalize_site_origin` / `configured_site_origin` / `resolve_site_origin` / `build_callback_url` plus a single `CALLBACK_PATH = "/payment/callback"` constant to services/zarinpal.py, mirroring the existing one-switch `ZARINPAL_USE_SANDBOX` pattern. The origin comes from ONE variable — `PUBLIC_SITE_URL` (alias `ZARINPAL_CALLBACK_BASE_URL`) — and the callback is composed as `<origin>/payment/callback`, so going live on a custom domain is a config change with zero code edits. Resolution order: env variable -> request origin (body hint, then `Origin`, then `Referer` header) -> loud `ZarinpalError`, so today still works while the variable is unset. Normalization is deliberately defensive: whitespace and stray quotes trimmed, trailing slashes and any path/query stripped, blank/whitespace-only values ignored, and a bare hostname or non-http(s) scheme rejected — a malformed `//payment/callback` is impossible. An unusable origin now returns a readable 500 instead of silently sending a broken callback that would strand buyers after they had already paid. routers/zarinpal_payment.py: `callback_origin` demoted from required to an optional fallback hint (the env var always wins, so the cutover never depends on what the browser reports), the resolved callback URL is logged, and `/config` additionally reports `site_origin_env_vars`, `site_origin_configured` and the composed `callback_url` so a domain switch can be confirmed without reading code (still no merchant id exposed). Verified with 14 normalization assertions (trailing slashes, multiple slashes, path+query, quoted value, localhost with port, blank/whitespace/None, bare host, ftp scheme, scheme-only, protocol-relative) plus fallback-used / blank-env-ignored / env-wins / secondary-var / loud-error cases — all PASS; a real sandbox request with `PUBLIC_SITE_URL="https://glowmarket.ir/"` composed `https://glowmarket.ir/payment/callback` and returned a valid authority. Grepped the payment path: no hardcoded published host remains. No behaviour regressed (server-side total, pre-redirect pending row, idempotent verify, cart cleared only on success).
